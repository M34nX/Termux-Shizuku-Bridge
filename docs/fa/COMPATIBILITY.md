# سازگاری و محیط پشتیبانی‌شده

این صفحه اطلاعات سازگاری پروژه‌های بالادستی را از وضعیت آزمایش خود TSB جدا می‌کند.

## ابزار خط فرمان پایتون

| مؤلفه | نیازمندی یا مرجع |
|---|---|
| برنامهٔ Termux | نسخهٔ رسمی فعلی؛ سیاست پشتیبانی اندروید پروژهٔ اصلی را دنبال کنید |
| Python | نسخهٔ ۳٫۱۰ یا جدیدتر |
| Shizuku | نصب و فعال باشد و به Termux مجوز داده شده باشد |
| rish | ابزار رسمی خروجی‌گرفته‌شده از یکپارچه‌سازی ترمینال Shizuku |
| فایل همراه | فایل rish_shizuku.dex خروجی‌گرفته‌شده برای برنامهٔ ترمینال |

ماتریس CI پایتون نسخه‌های ۳٫۱۰ تا ۳٫۱۳ را پوشش می‌دهد. نتیجهٔ commit جاری را در GitHub Actions ببینید.

## اپلیکیشن بومی اندروید

| مؤلفه | نسخه |
|---|---|
| حداقل Android SDK | 24 |
| Compile SDK | 35 |
| Target SDK | 35 |
| JDK | 17 |
| Android Gradle Plugin | 8.7.3 |
| Gradle | 8.9 |
| Kotlin | 2.0.21 |
| Shizuku API / Provider | 13.1.5 |

وابستگی انتخاب‌شدهٔ Shizuku API نسخهٔ 13.1.5 حداقل SDK برابر 24 اعلام می‌کند؛ بنابراین حداقل نسخهٔ اپ نیز API 24 است. اپ برای دریافت Binder از سازوکار رسمی ShizukuProvider استفاده می‌کند.

## نکات اندروید و Shizuku
- Shizuku از اندروید ۱۱ به بالا می‌تواند از طریق Wireless debugging راه‌اندازی شود.
- در دستگاه‌های بدون روت، سرویس مبتنی بر عیب‌یابی ممکن است پس از راه‌اندازی مجدد به شروع دوباره نیاز داشته باشد.
- اپ فقط دسترسی‌پذیری Binder را گزارش می‌کند؛ UID راه‌دور را نمایش نمی‌دهد و اجرای rish را اثبات نمی‌کند.
- TSB CLI از ابزار رسمی rish و فایل DEX همراه استفاده می‌کند. مخصوصاً در اندروید ۱۴ به بالا، از دستورالعمل فعلی Shizuku پیروی کنید.

## وضعیت اعتبارسنجی
- تست‌های واحد پایتون: نتیجهٔ commit جاری را در Actions بررسی کنید.
- ساخت APK اندروید: نتیجهٔ workflow ساخت اپ اندروید را بررسی کنید.
- آزمایش دستگاه واقعی: برای هر خانوادهٔ دستگاه و نسخهٔ اندروید همچنان لازم است.
- هیچ تضمین سازگاری همگانی برای همهٔ دستگاه‌ها و رابط‌های سازنده داده نمی‌شود.
