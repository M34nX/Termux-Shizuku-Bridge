# مدل امنیتی

TSB ابزار تشخیصی است، نه ابزار مدیریت مجوز یا روت.

## ابزار خط فرمان پایتون
- فقط probeهای ثابت، فقط‌خواندنی و موجود در فهرست مجاز داخلی به rish داده می‌شوند.
- ورودی کاربر داخل فرمان shell قرار داده نمی‌شود.
- برای subprocess زمان پایان مشخص وجود دارد.
- از shell=True، eval، فرمان دلخواه، تله‌متری و بارگذاری خودکار گزارش استفاده نمی‌شود.
- مسیرهای محلی و شناسه‌های سفارشی برنامه به‌طور پیش‌فرض پالایش می‌شوند.

## اپلیکیشن بومی اندروید
- اپ قابل‌مشاهده‌بودن بسته‌های Termux و Shizuku و دسترسی Binder شیزوکو را با API و Provider رسمی بررسی می‌کند.
- تابع Shizuku.requestPermission را فراخوانی نمی‌کند، فرمان shell اجرا نمی‌کند، UserService راه‌اندازی نمی‌کند و تنظیمات اندروید را تغییر نمی‌دهد.
- جزئیات دستگاه و وضعیت‌ها فقط به‌صورت محلی نمایش داده می‌شوند.
- گزارش فقط پس از فشردن دکمه توسط کاربر در حافظهٔ موقت کپی می‌شود.
- اپ مجوز INTERNET ندارد و درخواست شبکه ارسال نمی‌کند.

## کنترل کاربر

اعطای دسترسی Shizuku توسط خود برنامهٔ Shizuku مدیریت می‌شود. هر پیام درخواست مجوز را با دقت بررسی کنید. TSB از طرف کاربر مجوزی اعطا نمی‌کند.

## محدودیت دامنه

دسترسی‌پذیری Binder اثبات نمی‌کند که rish، فایل DEX همراه، مجوز Termux یا probeهای راه‌دور درست کار می‌کنند. برای بررسی انتها‌به‌انتهای پل از تشخیص‌های ثابت CLI استفاده کنید. نشان وضعیت در اپ موبایل را هرگز نشانهٔ دسترسی root تلقی نکنید.
