# معماری پروژه

TSB دو کلاینت مستقل دارد که هدف مشترک آن‌ها تشخیص محلی، شفاف و حریم‌خصوصی‌محور است.

## ابزار خط فرمان پایتون
- runner.py ابزار رسمی rish و فایل DEX همراه را پیدا می‌کند و فقط فرمان‌های ثابت موجود در فهرست مجاز داخلی را اجرا می‌کند.
- checks.py تصویر ساختاریافته‌ای از وضعیت محیط جمع‌آوری می‌کند.
- privacy.py مسیرهای محلی و شناسه‌های سفارشی برنامه را در گزارش پشتیبانی به‌طور پیش‌فرض پالایش می‌کند.
- report.py خروجی متنی و JSON می‌سازد.
- cli.py فرمان‌های doctor، status، report و version را ارائه می‌دهد.

CLI ابزار rish را به‌صورت subprocess و با timeout محدود اجرا می‌کند. مقدار دلخواه کاربر داخل فرمان shell قرار داده نمی‌شود.

## اپلیکیشن بومی اندروید
- MainActivity.kt صفحه، ترجیح زبان، بررسی بسته‌های قابل‌مشاهده و وضعیت دستگاه را مدیریت می‌کند.
- Jetpack Compose داشبورد فارسی و انگلیسی را نمایش می‌دهد.
- Shizuku API و Provider برای دریافت Binder و بررسی دسترس‌پذیری آن به کار می‌روند.
- گزارش تشخیصی پس از انتخاب کاربر، به حافظهٔ موقت کپی می‌شود.

نسخهٔ فعلی اپ موبایل درخواست مجوز ممتاز Shizuku نمی‌کند، UserService اجرا نمی‌کند، rish را فراخوانی نمی‌کند و فرمان راه‌دور اجرا نمی‌کند. دسترسی Binder از آماده‌بودن کامل پل rish جدا گزارش می‌شود.

## جریان داده

تمام بررسی‌های فعلی روی خود دستگاه انجام می‌شوند. هیچ backend، نقطهٔ تحلیل، تله‌متری یا بارگذاری خودکار گزارش تنظیم نشده است.

## محدودیت‌های طراحی
- بررسی فقط‌خواندنی وضعیت.
- حداقل‌سازی دسترسی‌ها و حفظ کنترل در اختیار کاربر.
- تفکیک روشن میان نصب برنامه، دسترسی Binder و اتصال انتها‌به‌انتهای rish.
- گزارش‌های کم‌خطر از نظر حریم خصوصی و ذخیرهٔ محلی زبان انتخابی.
